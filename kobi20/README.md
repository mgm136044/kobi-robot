# 코비 20축(Kobi-20) 로봇 모델: 소프트웨어 팀 인계 자료

코비 20축은 코비의 새 설계입니다. 관절이 20개이고(머리 2, 팔 3개씩 2, 다리 6개씩 2), 서보는 모두 Dynamixel(다이나믹셀)입니다. 이 폴더에는 이 로봇의 MuJoCo 모델(MJCF), URDF, 애니메이션 팀용 스켈레톤(리그) 파일, 외피 부품끼리 부딪히는 자세를 걸러 내는 규칙과 판정기가 들어 있습니다. 리타게팅(사람 동작을 로봇에 옮기는 일), 시뮬레이션, 애니메이션을 맡은 소프트웨어 팀을 위한 문서입니다. 인쇄 얼굴 판 코비(Open Duck Mini 바탕, 관절 14개)의 자료는 저장소의 다른 폴더(`printed_face/`)에 있고, 이 폴더와 섞이지 않습니다.

**꼭 알아 둘 점 세 가지입니다.**

1. **이 로봇의 걷기 정책(학습된 신경망)은 아직 없습니다.** 학습은 한 번도 돌리지 않았습니다. 관측값 배치나 행동 크기 같은 정책 규칙은 이 저장소에 없습니다. 아래에서 "번호"라고 하면 정책 행동 번호가 아니라 MuJoCo 모델의 구동기(액추에이터) 번호입니다.
2. **모든 숫자는 계산값과 시뮬레이션 값입니다.** 하드웨어는 제작되지 않았고, 서보 배치와 브래킷은 섀시 담당 팀원이 아직 확정하지 않은 설계안입니다. 배터리, 전압 안정기, 전자부품의 무게는 가정한 값입니다(7절).
3. **모든 관절 각도가 0인 자세("0 자세")는 이 로봇이 실제로 낼 수 없는 자세입니다.** 어깨 옆 관절(`*_shoulder_roll_joint`)의 허용 범위가 19.25도에서 시작하므로 0도는 범위 밖입니다. 스켈레톤 파일의 기준 자세(`rest`)가 바로 이 0 자세입니다. 로봇이 서 있는 기준 자세는 홈 자세(`home`)이고, 5절에 있습니다.

  skeleton/              애니메이션용 스켈레톤: kobi20_rig.blend/.fbx/.glb, kobi20_skeleton.bvh, skeleton.json, README.md

저장소 맨 위의 `tools/kobi20/`에는 URDF 경로를 바꾸는 `relocate_urdf.py`와 URDF 검사기 `verify_urdf.py`가, `tools/skeleton/`에는 스켈레톤 도구(`--profile kobi20` 선택지로 이 로봇도 만듭니다)가 있습니다.

URDF와 MJCF가 STL을 두 벌 갖지 않도록, 전체 URDF는 `mujoco/meshes/`의 같은 파일을 가리킵니다(경로 `../mujoco/meshes/이름.stl`). 그래서 `urdf/` 폴더만 다른 곳에 복사하면 메시가 없다는 오류가 납니다. 옮길 때는 `urdf/`와 `mujoco/meshes/`의 상대 위치를 지키거나, 메시를 `urdf/` 안으로 복사하고 URDF의 경로를 고치세요. 가벼운 판(`kobi20_v8_light.urdf`)은 `assets_light/`만 있으면 혼자 읽힙니다.

## 4. 좌표계, 단위, 부호 규칙

- **월드 좌표계**: MuJoCo 기준의 오른손 좌표계입니다. x가 로봇이 바라보는 앞쪽, y가 로봇의 왼쪽, z가 위쪽입니다. URDF에서는 골반(`pelvis`)이 뿌리 링크이고 같은 방향입니다. 확인한 근거: 앞코 덮개가 뒤꿈치 덮개보다 7.79 cm 앞(+x)이고, 왼쪽 장갑이 y = +11.29 cm, 오른쪽이 -11.29 cm이며, 머리 링크가 골반보다 26.6 cm 위입니다(`urdf/results/urdf_check.json`의 `frame_conventions`).
- **단위**: 길이 m, 질량 kg, 각도 rad(이 문서의 표는 도), 토크 N·m, 속도 rad/s입니다. 메시 STL도 m이고 크기 배율은 1입니다.
- **사원수 순서**: MuJoCo는 (w, x, y, z)입니다. ROS 등은 (x, y, z, w)이므로 변환이 필요합니다.
- **링크 좌표계는 모두 같은 방향**입니다. 링크 사이 오프셋은 위치(`xyz`)만 있고 URDF의 `rpy`는 전부 0입니다.
- **메시 파일**: STL은 이진 형식, 단위 m, 크기 배율 1입니다. 색은 빨강(섀시 부품)과 흰색(외피) 두 가지뿐입니다.
- **뿌리**: MJCF에서는 `pelvis` 몸체가 자유 관절 `root`(위치 3개, 사원수 4개)를 직접 갖습니다. URDF로 읽으면 뿌리가 세계에 고정되고 자유 관절이 없습니다. 떠 있는 로봇으로 쓰려면 pinocchio의 `JointModelFreeFlyer()` 같은 것을 붙이세요.

### 4.1 오른쪽 관절의 거울 축

오른쪽의 `hip_yaw`, `hip_roll`, `ankle_roll`, `shoulder_roll` 네 관절은 축이 왼쪽과 반대 방향(-z 또는 -x)으로 달려 있습니다. 그래서 **왼쪽과 오른쪽이 같은 부호의 각도를 가지면 몸이 거울처럼 대칭으로 움직입니다.** 예를 들어 어깨 옆 +는 양쪽 팔이 모두 몸에서 벌어지는 방향이고, 엉덩이 비틀기 +는 양쪽 발끝이 모두 바깥쪽으로 돕니다. 반대로 앞뒤(pitch)와 팔꿈치, 무릎, 목은 양쪽 모두 +y 축이라 같은 부호가 같은 방향입니다. 사람 쪽 각도를 "월드 방향"(예: 왼쪽이 +)으로 뽑았다면, 오른쪽의 이 네 관절은 부호를 맞춰 주어야 합니다. 관절 범위는 왼쪽과 오른쪽이 같은 숫자입니다(인쇄 얼굴 판은 달랐습니다).

### 4.2 각도 +가 어느 쪽으로 움직이는가

한 관절만 +0.2 rad 움직이고 먼 쪽 점이 어디로 가는지 잰 결과입니다(`urdf/results/sign_conventions.json`).

| 관절 | + 방향의 움직임 |
|---|---|
| 목 좌우 | 고개가 왼쪽(+y)으로 돌아감 |
| 목 끄덕임 | 얼굴이 아래로 숙여짐(범위가 -16.75~12도라서 위로 드는 쪽이 더 넓음) |
| 어깨 앞뒤 | 손 자리가 뒤(-x)로 감. 팔을 앞으로 올리는 쪽은 음수(범위 -96~3.75도) |
| 어깨 옆 | 양쪽 팔이 몸에서 벌어짐(왼쪽 +y, 오른쪽 -y) |
| 팔꿈치 | 손이 뒤(-x)로 감. 앞으로 굽히는 쪽이 음수(범위 -61~3도) |
| 엉덩이 비틀기 | 양쪽 발끝이 바깥으로 돌아감 |
| 엉덩이 옆 | 양쪽 다리가 벌어짐(왼쪽 +y, 오른쪽 -y) |
| 엉덩이 앞뒤 | 발목이 뒤(-x)로 감. 다리를 앞으로 드는 쪽이 음수 |
| 무릎 | 발목이 뒤(-x)로 감 = 굽힘 |
| 발목 앞뒤 | 발끝이 아래로 내려감 |
| 발목 옆 | 양쪽 발의 바깥쪽 가장자리가 올라감 |

예를 들어 무릎 +0.5 rad를 주면 발목이 뒤로 4.41 cm, 어깨 앞뒤 -1 rad를 주면 손 자리가 앞으로 10.62 cm 갑니다. 인쇄 얼굴 판의 약속("어깨는 음수이면 팔이 위로 올라가고 양쪽 부호가 같다")과 어깨 앞뒤는 같지만, 목 끄덕임은 둘 다 +가 고개를 숙이는 방향입니다.

출처: `urdf/results/urdf_check.json`, `urdf/results/sign_conventions.json`(MuJoCo로 읽어 직접 잰 값).

## 5. 홈 자세와 0 자세

**홈 자세**는 MJCF의 키프레임 `home`입니다. 0이 아닌 값은 다섯 종류뿐이고 나머지 관절은 0입니다.

| 관절 | 홈 자세 값 |
|---|---|
| 어깨 옆(`*_shoulder_roll_joint`) 좌우 | 20 도(0.349066 rad) |
| 팔꿈치(`*_elbow_joint`) 좌우 | -18 도(-0.314159 rad) |
| 엉덩이 앞뒤(`*_hip_pitch_joint`) 좌우 | -6.193 도(-0.108091 rad) |
| 무릎(`*_knee_joint`) 좌우 | 8.594 도(0.150000 rad) |
| 발목 앞뒤(`*_ankle_pitch_joint`) 좌우 | -2.401 도(-0.041909 rad) |

- 뿌리(골반)의 홈 위치는 (0, 0, 0.185802) m, 방향은 사원수 (1, 0, 0, 0)입니다. 엉덩이, 무릎, 발목 값은 무게 중심이 발목 축 바로 위에 오도록 모델 생성기가 풀어 낸 값입니다.
- 키프레임에는 위치 서보의 목표값(`ctrl`)도 들어 있습니다. 중력 때문에 처지는 만큼 `qpos`와 조금 다릅니다(예: 무릎 목표 0.1445 rad, 실제 0.15 rad). 이 목표값을 주고 시뮬레이션하면 2초(1,000걸음) 동안 넘어지지 않고 서 있는 것을 확인했습니다(몸통 기울기 0.99999999, 아래 10절의 서 있기 한계는 따로 있습니다).
- 100 g판(`*_reg100.xml`)은 무게가 가벼워 홈 자세 값이 조금 다릅니다(엉덩이 -6.511도, 발목 -2.083도, 골반 높이 0.185781 m).

**0 자세는 서보가 낼 수 없는 자세입니다.** 어깨 옆 범위가 19.25도부터라 0도는 범위 밖입니다. MuJoCo는 시뮬레이션 중에는 관절 범위를 지키려 하지만, 계산(순기구학)에서는 0 자세를 그대로 계산해 줍니다. 그래서 0 자세는 **위치 계산을 대조하는 용도로만** 쓰세요. 보여 주거나 시작 자세로 쓸 때는 홈 자세를 쓰세요. 외피 결합 한계 판정기도 0 자세를 위반으로 판정합니다(8절). 스켈레톤 파일의 기준 자세(`rest`)가 이 0 자세이고, 같은 파일의 `home` 동작이 서 있는 자세입니다.

출처: `mujoco/kobi20_v8.xml`, `mujoco/kobi20_v8_reg100.xml`(키프레임 `home`), 홈 자세 서 있기는 MuJoCo 3.14.0으로 직접 돌린 결과입니다.

### 6.1 MuJoCo

```python
import mujoco

model = mujoco.MjModel.from_xml_path("kobi20/mujoco/scene_kobi20_v8.xml")   # 바닥과 조명 포함
# model = mujoco.MjModel.from_xml_path("kobi20/mujoco/kobi20_v8.xml")       # 바닥 없는 본체만
data = mujoco.MjData(model)
key = mujoco.mj_name2id(model, mujoco.mjtObj.mjOBJ_KEY, "home")
mujoco.mj_resetDataKeyframe(model, data, key)
data.ctrl[:] = model.key_ctrl[key]      # 위치 서보 목표(rad). 순서는 3절 표의 번호
mujoco.mj_forward(model, data)
```

MuJoCo 3.14.0으로 직접 읽은 결과입니다(몸체 수 27은 `world`를 포함합니다).

| 파일 | 몸체 | 관절 | 구동기 | 상태 변수 nq / 속도 nv | 전체 무게 |
|---|---|---|---|---|---|
| `mujoco/kobi20_v8.xml` | 27 | 21(자유 1 + 20) | 20 | 27 / 26 | 4.0724 kg |
| `mujoco/scene_kobi20_v8.xml` | 27 | 21 | 20 | 27 / 26 | 4.0724 kg |
| `mujoco/kobi20_v8_reg100.xml`, `scene_kobi20_v8_reg100.xml` | 27 | 21 | 20 | 27 / 26 | 3.3524 kg |
| `urdf/kobi20_v8.urdf`, `urdf/kobi20_v8_light.urdf` | 30 | 20 | 0 | 20 / 20 | 4.0724 kg |

- 구동기는 위치 서보(`<position>`)이고 목표는 라디안, 목표 범위는 관절 범위와 같습니다. 물리 간격은 0.002 s입니다. 센서는 IMU(자이로, 가속도, 자세, 속도), 발 위치와 속도가 있습니다.
- **충돌 모양**: 상자 5개(몸통 2, 머리 1, 발 2)와 캡슐 8개(위팔, 아래팔, 허벅지, 정강이 좌우)뿐이고, 81개의 메시는 모두 보이기만 하는 것입니다(충돌 없음). 충돌은 `<contact>`의 쌍 목록으로 켭니다. 본체 파일에 11쌍(발끼리, 정강이끼리, 허벅지끼리, 발과 몸통, 발과 반대편 정강이 2, 팔 4개와 몸통 중심부)이 있고, 바닥 파일에 몸통과 머리의 바닥 충돌 2쌍이 더 있으며, 발 상자는 바닥과 항상 충돌합니다.
- 오른발 상자는 왼발보다 좌우 폭만 조금 큽니다(8.35 cm 대 8.09 cm). 모델에 이미 있는 값이며 오류가 아닙니다.

### 6.2 MJX(GPU/JAX 버전의 MuJoCo)

MJX는 **같은 MJCF 파일을 그대로 씁니다.** MJX용 파일이 따로 없습니다.

```python
import mujoco
from mujoco import mjx

model = mujoco.MjModel.from_xml_path("kobi20/mujoco/scene_kobi20_v8.xml")
data = mujoco.MjData(model)
mjx_model = mjx.put_model(model)
mjx_data = mjx.put_data(model, data)
```

이 모델은 MJX가 다루는 충돌 모양(상자, 캡슐, 바닥 평면)만 씁니다. 메시는 충돌에 쓰지 않습니다. `uv run ... --with mujoco-mjx --with jax`로 이번에 직접 확인한 결과(mujoco-mjx 3.14.0, jax 0.11.2, CPU, 32비트 실수): 홈 자세에서 키프레임 `ctrl`을 주고 100걸음(0.2초) 돌린 뒤 일반 MuJoCo와 `qpos`를 비교하니 최대 차이가 820 g판 2.7e-6, 100 g판 3.1e-6이었습니다. 5 cm 높이에서 떨어뜨려 200걸음(0.4초)을 돌렸을 때도 최대 차이 1.1e-5였습니다(접촉 8개). 이 확인은 CPU에서 했고 GPU에서는 해 보지 않았습니다. 이 로봇으로 학습을 돌려 본 것이 아닙니다.

### 6.3 URDF

```python
import mujoco
model = mujoco.MjModel.from_xml_path("kobi20/urdf/kobi20_v8.urdf")   # 관절 20개, 구동기 없음, 뿌리는 세계에 고정
```

```python
import pinocchio as pin
path = "kobi20/urdf/kobi20_v8.urdf"
model = pin.buildModelFromUrdf(path, pin.JointModelFreeFlyer())          # nq 27 = 뿌리 7 + 관절 20
gm = pin.buildGeomFromUrdf(model, path, pin.GeometryType.VISUAL, package_dirs=["kobi20/urdf"])   # 메시 81개
```

- URDF 파일은 `<mujoco><compiler .../></mujoco>` 태그를 갖고 있어 MuJoCo가 그대로 읽습니다. 다른 읽개는 이 태그를 무시합니다.
- 메시 경로는 모두 URDF 파일 위치 기준의 상대 경로입니다(`package://`나 절대 경로가 없습니다).
- 힘(`effort`)은 구동기 힘 범위 상한(정지 토크), 속도(`velocity`)는 무부하 속도입니다(3절). `<dynamics>`에 관절 감쇠와 마찰이 들어 있습니다. 위치 서보 강성(kp)과 회전 관성(armature)은 URDF에 적을 칸이 없어서 CSV와 MJCF에만 있습니다.
- **충돌**: 상자는 그대로 상자이고, 캡슐은 "원기둥 1개 + 구 2개"의 합집합으로 바꿨습니다(캡슐이 정의상 그 합집합이라 모양이 똑같습니다). 이름은 `left_thigh_cylinder`, `left_thigh_cap_top`, `left_thigh_cap_bottom` 식입니다. 메시 충돌 모양은 없습니다. **MJCF의 충돌 쌍 목록은 URDF에 적을 방법이 없습니다.** URDF를 그대로 충돌 검사기에 넣으면 상자와 캡슐이 서로 겹쳐 있는 곳(몸통 상자와 팔 캡슐 등)이 충돌로 잡힐 수 있으니, 어떤 쌍을 검사할지는 `mujoco/kobi20_v8.xml`의 `<contact>`를 보고 직접 거르세요.
- 가벼운 판(`kobi20_v8_light.urdf`)은 메시 면 수를 706,334개에서 101,822개로 줄였습니다(5 MB). 줄이면서 생긴 오차는 면 위 표본점 양방향 측정으로 최대 3.39 mm(얇은 화면 테두리 한 곳), 대부분 1.4 mm 이하, 상위 99% 오차 최대 1.35 mm입니다(`urdf/results/light_mesh_error.json`). 링크 위치, 무게, 관성, 충돌 모양은 전체판과 같습니다. 보이는 모양 용도입니다.
- 이번에 `yourdfpy`, `urdfpy`, RViz, PyBullet, Isaac에서는 읽어 보지 않았습니다. 읽은 것은 MuJoCo 3.14.0과 pinocchio 4.1.0뿐입니다.

출처: `tools/kobi20/verify_urdf.py` 실행 결과, `urdf/results/`.

## 7. 무게

MJCF의 모든 몸체 질량을 합친 값입니다. 안정기만 다른 두 판이 있습니다.

| 모델 | 전체 무게 |
|---|---|
| `kobi20_v8`(안정기 820 g, 기본) | 4.0724 kg |
| `kobi20_v8_reg100`(안정기 100 g) | 3.3524 kg |

4.0724 kg의 내역(`mujoco/build_info_kobi20_v8.json`)은 서보 958.4 g, 3D 프린트 섀시 부품(브래킷) 417.3 g, 외피 1,362 g, 가짜 모터 84.7 g, 가정한 덩어리 1,250 g입니다. 가정한 덩어리는 배터리 180 g(골반 아래 판), 전압 안정기 820 g(골반 위 판, 데이터시트의 상한값), 라즈베리파이와 서보 통신 기판과 선 100 g(몸통), 머리의 화면과 카메라와 스피커 150 g(머리)입니다. 100 g판은 안정기를 100 g으로 둔 것이라 골반만 다릅니다(527.180 g, 나머지 링크는 같음).

- 링크별 무게는 `urdf/links_kobi20_v8.csv`에 있습니다(예: 골반 1,247.180 g, 몸통 776.209 g, 머리 `neck_pitch_link` 653.887 g).

## 8. 외피 결합 한계(`shell_rules/`)

관절 범위(3절)는 관절 하나하나의 값입니다. **여러 관절이 함께 움직이면 범위 안의 자세라도 외피 부품끼리 부딪힐 수 있습니다.** 예를 들어 팔을 앞으로 올리면서 목을 돌리면 소매와 머리 껍데기가 겹치고, 엉덩이를 많이 비틀면 반대쪽 다리와 겹칩니다. 이런 제한을 "결합 한계"(규칙 A~G)로 정리해 두었고, 판정기와 함께 `shell_rules/`에 넣었습니다. **MJCF와 URDF는 이 제한을 막지 않습니다.** 관절 범위 안이라는 이유로 안전하다고 보면 안 됩니다. 관절 범위 안에서 균일하게 무작위로 고른 5,000개 자세 가운데 4,975개(99.5%)가 규칙을 하나 이상 어겼습니다(20개 관절 모두를 함께 무작위로 움직인 극단적인 경우이긴 합니다).

사용법은 `shell_rules/README.md`에 있습니다. 한 줄 예시는 다음과 같습니다.

```
python3 -I -B kobi20/shell_rules/check_pose.py --pose left_hip_yaw_joint=20 --unit deg
```

이 규칙은 20축 이전의 25축 모델에서 잰 값에 고정 관절 값 0을 대입해 만든 것이고, 20축 자세에서 외피 간격을 새로 재지는 않았습니다. 정리하면 "25축에서 안전했던 자세의 부분집합"이라는 근거입니다.

### 9.1 URDF와 MJCF 비교(`tools/kobi20/verify_urdf.py`, 결과 `urdf/results/urdf_check.json`)

- ① 한 일: URDF를 MuJoCo로 다시 읽어 MJCF와 비교했습니다. 자세는 0 자세 1개, 홈 자세 1개, 관절 범위 안의 무작위 20개(고정 시드)입니다. 같은 URDF를 pinocchio로도 읽어 비교했습니다. 전체판과 가벼운 판 둘 다 했습니다.
- ② 값의 뜻과 결과: 모든 링크 원점 위치 오차는 전체판 0.0000 mm(한도 0.01 mm), 관절 위치와 무게 중심 오차도 0.0000 mm, 링크별 무게 오차와 전체 무게 오차는 0 g(MJCF 4,072.437 g, URDF 4,072.437 g, 한도 0.1 g), 관성 텐서 상대 오차 최대 4.3e-10, 충돌 모양 위치 오차 6.2e-14 mm 이하, 보이는 메시 81개의 위치 오차 0.0000 mm입니다. pinocchio로 읽어도 링크 틀 위치 오차 5.6e-14 mm, 전체 무게 중심 오차 5.6e-14 mm, 전체 무게 4,072.437 g, 관절 범위 오차 0, 보이는 메시 81개와 충돌 모양 29개가 읽혔습니다. 오차가 정확히 0으로 나오는 이유는 URDF의 값이 MJCF를 컴파일한 값을 유효숫자 10자리로 적은 것이라서입니다.
- ③ 가벼운 판: 같은 항목이 모두 통과했고, 가벼운 판은 메시 모양만 달라서 보이는 메시 원점은 최대 1.33 mm 어긋납니다(MuJoCo가 메시를 자기 관성 기준으로 다시 맞추기 때문입니다. 링크 위치와 무게에는 영향이 없고, URDF 글자가 메시 경로만 빼고 전체판과 같음을 따로 확인했습니다).
- ④ 구조: 링크 29개, 관절 28개(회전 20 + 고정 8), 뿌리 하나(`pelvis`), 순환 없음, 참조한 STL 81개 모두 존재, 쓰지 않는 STL 없음, 전체 URDF가 쓰는 STL 집합이 `mujoco/meshes/`와 MJCF의 메시 집합과 같습니다.
- ⑤ pinocchio에서는 관절 순서가 MJCF와 다릅니다(3절). 이름 집합은 같습니다.

### 9.2 스켈레톤(`skeleton/README.md`의 7절에 자세히)

## 10. 알려진 한계

1. **걷기 정책이 없습니다.** 걷기 학습은 돌리지 않았고, 이 로봇의 관측, 행동, 보상 규칙은 이 저장소에 없습니다.
2. **모든 값은 계산값입니다.** 하드웨어는 제작되지 않았습니다. 서보 배치와 브래킷은 섀시 담당 팀원이 아직 확정하지 않았습니다. 최종 모델 전체에 대한 별도 검증자의 독립 검증은 받지 않았습니다(개발 중에 받은 독립 검토의 지적은 반영했습니다).
3. **로봇은 서보 강성 1배로는 스스로 서지 못합니다(정책이 없는 모델 기준).** 모델 생성 기록의 서 있기 시험(820 g판, 60초)에서 강성 1배는 35.56초에 몸통이 10도를 넘게 기울어 넘어졌고, 강성 2배는 끝까지 0.01도만 기울었습니다. 홈 자세에서 키프레임 목표를 줘서 2초 서 있게 한 것(5절)은 넘어지기까지 걸리는 시간보다 짧은 시험입니다.
4. **외피 결합 한계는 URDF와 MJCF에 없습니다**(8절).
5. **0 자세는 범위 밖입니다**(5절).
6. **가정한 무게**(7절): 배터리, 안정기, 전자부품, 머리 부품과 재료, 채움은 가정입니다. 서보와 가짜 모터는 보이는 모양이 없고 무게만 있습니다. 가짜 모터의 나사 구멍, 케이블, 출력물 강도, 실제 출력 무게는 보지 않았습니다.
7. **힘 한계는 정지 토크이고 연속 토크가 아닙니다.** 전압은 모델 설정(XM430 12 V, XL330 5 V 기준)을 따랐습니다. 실제 서보 특성과 맞춰 보지 않았습니다. 리타게팅에서는 한계를 넘는 빠른 동작을 거르는 용도로만 쓰는 것이 안전합니다.
8. **메시**: MuJoCo가 STL 면 20만 개까지만 읽기 때문에 큰 외피 부품(머리 껍데기는 원래 약 22만 면)은 모델 생성기가 0.05~0.1 mm 오차 안에서 줄여 두었습니다(머리 약 4만 면). 원본 풀 해상도 외피는 이 저장소에 없습니다.
9. **URDF의 충돌 쌍 목록 없음, 캡슐 대신 원기둥과 구**(6.3절).
10. **MJX는 CPU에서 100걸음 비교만 했습니다**(6.2절). GPU에서 학습을 돌려 본 것이 아닙니다.
11. **홈 자세 값의 소수점 차이**: 이 문서와 `urdf/joints_kobi20_v8.csv`는 MJCF 키프레임의 값(-6.193도, -2.401도)을 씁니다.

## 11. 출처와 라이선스

- 이 폴더의 모델은 섀시(브래킷)와 외피 모두 우리 팀이 만든 것이고, 서드파티 메시는 없습니다. 섀시는 로봇 OP3와 같은 20축 구성으로 팀원이 설계했고, 외피는 팀의 코비 모델(코리 캐릭터 옷)에서 가져왔습니다. 자세한 것은 저장소 `NOTICE.md`의 7절에 있습니다.
