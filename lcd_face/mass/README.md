> 저장소 사본 안내: 이 문서는 작업 폴더의 7b판 슬라이서 README(`slicer_weights_v7b_20261104/README.md`)와 6판 슬라이서 README(`slicer_weights_20261104/README.md`)의 내용을 합쳐 `lcd_face/mass/`용으로 새로 쓴 것입니다. 개인 컴퓨터의 절대 경로와 임시 폴더 경로는 평범한 설명으로 바꿨고, 숫자는 원본 그대로입니다. 이 저장소에는 `parts.csv`, `parts_changed_v7b.csv`, `bodies.csv`, `skeleton_parts.csv`, `settings/`만 넣었고, 스크립트(`scripts/`)와 실행 기록(`raw/`)은 개인 경로가 들어 있어 넣지 않았습니다(8절). 1차 공개(커밋 d46fc16)의 6판 표(`parts.csv`, `bodies.csv`)와 6판 README는 git 이력에 있습니다.

## 3. 어떻게 쟀나

1. 부품마다 STL을 슬라이서에 넣어 G-code를 만들고, 그 안의 "filament used [mm]"(밀어낸 필라멘트 길이)에 필라멘트 단면적(지름 1.75 mm)과 밀도를 곱해 그램을 구했습니다. G-code가 직접 적는 "filament used [g]"는 소수 둘째 자리까지라 0.05 g 같은 작은 부품에서 거칠어서, 길이에서 다시 계산했습니다. 두 값은 모두 일치합니다.
2. 받침(서포트)은 따로 쟀습니다. 받침을 끈 채로 자른 값이 "설치 질량"(본문 숫자)이고, 보통 설정에서 받침을 켜고 한 번 더 잘라 "받침 켠 값 - 받침 끈 값"을 받침 그램으로 적었습니다. 받침을 끈 G-code에는 받침 선이 0줄임을 확인했습니다. 챙(brim), 스커트, 프라임 타워도 모두 껐습니다.
3. 정화(purge) 선을 뺐습니다. 슬라이서가 기본으로 주는 Marlin 시작 코드는 시작 때 필라멘트를 약 50 mm 밀어내고, 이것이 그램에 더해집니다(첫 시험에서 0.05 g짜리 핀이 0.23 g으로 나왔습니다). 그래서 시작·종료 코드에서 밀어내기를 모두 없앴고, 부품 그램에는 부품만 들어갑니다.
4. 부품은 내보낸 STL의 방향 그대로 잘랐습니다(바닥으로 내리는 것만 슬라이서가 합니다). G-code의 높이(max_z_height)가 STL 높이와 같은 것을 부품마다 확인했습니다. 따로 쓴 부품 방향 규칙은 없습니다.
5. 머리 껍데기와 흰 얼굴은 한 장이 베드(256 mm)보다 커서 문서대로 왼쪽/오른쪽 반쪽 STL(`print/head/A_HeadShell_L.stl`, `_R`, `print/face/Face_WhiteFace_L.stl`, `_R`)을 따로 잘라 더했습니다. 나머지 61개는 한 장으로 잘랐습니다(Face_LCD_bezel도 118.7 mm라 한 장).
6. 부품 STL 위치: 이 저장소의 `lcd_face/print/`에 있는 STL 14개(머리 반쪽 2, 흰 얼굴 반쪽 2, Neck, Top_plate, 장갑 2, LCD 테두리, Head_frame_LCD, LCD_mount, LCD_mount_pin, Neck_gap_shield, Pi4_head_bracket)는 그것을 쓰고(문서가 "새로 만들었거나 바뀐 부품"으로 적은 것), 나머지 51개는 인쇄 얼굴 판의 원래 인쇄 파일(`print_v8`, 이 저장소의 `printed_face/print/`와 같은 파일)에서 가져왔습니다. 모든 부품의 STL 부피 x 1.24 값이 시뮬레이터의 솔리드 질량과 0.1 g 안에서 맞는 것을 확인했습니다(6판 때 63개 합 1309.85 g 대 1309.86 g입니다. 7b판의 `parts.csv`는 63개 합이 STL 기준 1259.875 g, 시뮬레이터 기준 1259.877 g으로 0.002 g 다릅니다).
7. 7b판 설정 JSON 7개가 6판 설정 파일과 바이트 단위로 같음을 작업 폴더에서 `cmp`로 다시 확인했습니다. 가상 프린터, 보통(P1)/튼튼(P2) 설정, 정화선 없는 시작·종료 코드, PLA 1.24 g/cm3까지 6판과 같습니다.

## 5. 메모리와 시간

- 슬라이서는 한 번에 하나만 돌렸고 `/usr/bin/time -l`로 매번 최대 메모리를 쟀습니다(6판 때는 0.25초마다 감시해 3.7 GB를 넘으면 강제 종료하도록 했지만 발동하지 않았습니다).
- 6판 때 가장 작은 부품(지름 3 mm 핀)은 약 50 MB, 가장 큰 것(머리 반쪽에 받침까지 켠 경우)은 최대 977 MB(0.95 GB)였고, 한 번 자르는 데 0.3~12초 걸렸습니다. 7b판 슬라이스는 최대 메모리 1,002 MB(머리 반쪽 받침 켠 경우), 한 번에 0.3~5.8초였고 실패와 강제 종료는 없었습니다. 4 GB 기준에 한참 못 미칩니다.
- 6판 때 슬라이서 실행은 약 240번(부품 65개 x 3 + 뼈대 13개 x 3 + 방향 시험 4)이었고, 7b판은 바뀐 부품만 21회 돌렸습니다(실행마다의 원본 기록 21줄).

## 6. 부품 표와 몸체 표

- `parts.csv`: 63개 인쇄 부품 각각의 파일, 재료/색, 솔리드 g, P1 g, P2 g, 두 비율, 받침 g(P1), 메모, 속한 시뮬레이터 몸체. "model solid g"는 STL 부피 x 1.24이고, 마지막 열은 시뮬레이터가 쓰는 솔리드 값입니다(7b판 4개 부품은 7b판 `parts.json` 값). 재료는 문서에 적힌 것이 없어서 63개 전부 PLA로 보았고, 색은 시뮬레이터 모델의 색 값에서 읽었습니다.
- `parts_changed_v7b.csv`: 7b판에서 바뀐 부품 4개와 시험 조각 2개의 6판, 7판, 7b판 비교 표(위 2절 표의 원본)입니다.
- `bodies.csv`: MuJoCo 몸체별로 7b판 XML 질량, 그 안의 인쇄 부품 솔리드 합, P1 합, P2 합, 새 몸체 질량(= XML 질량 - 솔리드 합 + 슬라이서 합. 인쇄가 아닌 부품은 그대로), 비교용으로 7판과 6판의 같은 열을 넣었습니다. 1차의 6판 `bodies.csv`에 있던 "mapped parts" 열과 뼈대 참고 열 두 개는 이 표에 없습니다(뼈대 참고값은 `skeleton_parts.csv`).
- 부품을 몸체에 붙인 방법: 작업 폴더의 `mujoco/parts.json`(저장소 밖 파일)의 `parent` 값(시뮬레이터를 만들 때 부품을 붙인 방식 그대로)을 XML 몸체 이름에 대응시켰습니다. head는 kobi_head, neck은 kobi_neck_link, arm_L/arm_R는 kobi_arm_left/right, trunk는 trunk_assembly이고, 발 덮개는 foot_assembly와 foot_assembly_2, 다리 보호대는 knee_and_ankle_assembly_2와 _4입니다. 6판 때는 이 방식으로 kobi_head의 부품 질량 합이 XML 값과 정확히 일치함을 확인했습니다. 7b판의 XML 값 636.237 g은 `../mujoco/sim_report.json`의 머리 질량 636.2 g과 같습니다.

## 7. 뼈대(Open Duck Mini v2) 인쇄 부품, 한계와 주의

- 지금 시뮬레이터가 쓰는 뼈대 메시(`mujoco/assets/trunk_bottom.stl` 등 28개)는 삼각형 약 104개짜리 단순화 모양(5,284바이트)이라 눈으로 보기용이고 인쇄용이 아닙니다.
- 다만 업스트림 Open_Duck_Mini 저장소의 상세 CAD 메시(미터 단위)에서 시뮬레이터에 남아 있는 뼈대 부품 13종을 mm로 바꿔 같은 두 설정으로 잘랐습니다(6판 때). 공식 인쇄 파일이 아니라 조립 좌표계 그대로의 CAD 메시라서, 방향이 실제 출력과 다르고 받침 그램은 의미가 약합니다. 질량만 참고하세요. 결과는 `skeleton_parts.csv`이고, 발 바닥 TPU는 TPU 밀도 1.21로 쟀습니다. 몸체 질량에는 이 값을 반영하지 않았습니다. 업스트림 문서(`docs/sim2real.md`)가 "인쇄 속채움 때문에 부품 질량을 슬라이서 추정값으로 덮어쓴다"고 적고 있어 뼈대 몸체 질량에는 이미 속채움이 들어 있다고 보는 것이 맞지만, 그 일치를 직접 확인하지는 못했습니다(그래서 "측정 못 함"). 같은 설정으로 슬라이스한 뼈대 인쇄 부품 합은 P1 398.6 g, P2 485.7 g입니다.
- 슬라이서 추정은 실제 저울값과 5~10% 어긋날 수 있습니다. 실제 필라멘트 밀도(색마다 다름), 프린터의 흐름 보정, 속채움이 실제로 채워지는 양이 다르기 때문입니다. 이 오차는 출력한 부품 몫(7b판 머리는 P1 321.5 g)에만 붙고 사서 넣는 부품(267.9 g)에는 붙지 않습니다. 출력 부품이 10% 무거우면 머리는 589.4 + 32.2 = 621.6 g으로 학습 상한 638.3 g 안이고, 5% 어긋남(약 605.5 g)까지도 상한 안입니다. 이 추정은 질량만 바꾸었으며 무게중심과 관성은 다시 계산하지 않았습니다. 머리 껍데기 반쪽 하나와 윗판(Top_plate) 하나를 실제로 달아 보면 보정 비율을 쉽게 얻을 수 있습니다.
- **7b판 껍데기 0.9 mm의 불확실성.** P1의 벽 3겹(바깥 0.42 + 안쪽 0.45 + 0.45 = 1.32 mm)이 0.9 mm 피부에 못 들어가서 슬라이서가 벽 수를 스스로 줄여 채웁니다. 이 두께 근처의 추정은 6판의 1.2 mm보다 불확실합니다. 특징 둘레 5 mm 띠는 1.2 mm 그대로라서 7판보다 P1/솔리드 비율이 조금 높습니다(0.868 대 0.865). 껍데기 반쪽 하나를 저울로 달아 보는 것이 가장 좋습니다.
- 알아 둘 편향: 슬라이서는 선의 단면을 둥근 모서리 직사각형으로 계산해서, 꽉 찬 부품도 기하학적 부피보다 6~7% 덜 나옵니다(예: 3 mm 핀과 소매 단(cuff)이 0.93~0.94배). 그래서 "거의 솔리드"인 부품의 비율이 1.00이 아니라 0.93~0.94로 나오는 것은 오류가 아니라 슬라이서의 계산 방식입니다.
- Neck_gap_shield(두께 0.9 mm)는 층 높이 0.2 mm에 맞춰 1.0 mm로 인쇄되어 솔리드 계산(1.62 g)보다 무거운 1.78 g이 나옵니다. 슬라이서가 그렇게 자르므로 그대로 두었습니다.
- 받침: 6판 때 모델 방향 그대로 자르면 머리 반쪽이 받침을 약 250 g이나 썼습니다(이음 면을 바닥에 눕혀 자르면 약 181 g). 7b판 껍데기의 받침 519.5 g은 두 반쪽 합이며 세운 방향 때문입니다. 어느 쪽이든 설치 질량에는 포함되지 않습니다.
- 질량만 바꾼 것입니다. 부품이 가벼워지면 관성 모멘트와 무게중심도 조금 달라지는데, 이 슬라이서 작업에서는 다시 계산하지 않았습니다(7b판 모델 자체의 관성과 무게중심은 `../mujoco/kobi_scene.xml`의 머리 몸체에 솔리드 기준으로 들어 있습니다). 정책에 넣을 때는 새 몸체 질량으로 관성도 비례해서 줄이는 것이 가장 간단한 근사입니다.
- 자석과 나사는 모델에 가정 값으로만 들어 있습니다(머리 3.6 g, 몸통의 선과 나사 60 g). 실제 개수로 달아서 확인해야 합니다. 접착제와 마이크 SM 6핀 분리 커넥터는 모델 질량에 들어가지 않았습니다. 서보·전자부품·선·천 레깅(Fabric legging 2 x 20 g)은 인쇄 부품이 아니라서 그대로입니다.
