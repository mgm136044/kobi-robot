# 코비 20축 외피 결합 한계 규칙과 판정기

관절 범위(MJCF, URDF, `kobi20/README.md` 3절)는 관절 하나하나에 정한 값입니다. 로봇을 실제로 움직일 때는 **여러 관절이 동시에 움직이면서 외피 부품끼리 부딪히는 자세**가 문제입니다. 예를 들어 팔을 앞으로 들면서 고개를 팔 쪽으로 돌리면 소매와 머리 껍데기가 겹치고, 엉덩이를 바깥으로 많이 비틀면 반대쪽 다리와 겹칩니다. 모든 관절이 자기 범위 안에 있어도 그렇습니다. 이 폴더는 그런 "결합 한계"를 규칙(A~G)으로 정리한 데이터와, 자세가 규칙을 어기는지 알려 주는 판정기입니다.

**MuJoCo 모델과 URDF는 이 규칙을 막지 않습니다.** 판정기도 기본으로 꺼져 있고 어떤 환경에도 연결되어 있지 않습니다. 이 규칙은 **임시값**이며 모든 숫자가 바뀔 수 있습니다. 20축 자세에서 외피 간격을 새로 재지 않았고, 25축 설계에서 재어 둔 값에 고정한 관절의 값 0을 대입해 만들었습니다(20축 자세는 25축에서 재었던 자세의 부분집합이라는 근거입니다).

## 1. 왜 관절 범위만으로는 부족한가

관절 범위 안에서 균일하게 무작위로 고른 자세 5,000개(관절 20개 모두를 한꺼번에 무작위로 움직인 극단적인 경우)를 판정기에 넣었더니 4,975개(99.5%)가 규칙을 하나 이상 어겼습니다. 규칙을 어긴 자세가 모두 실제로 부딪히는 것은 아닙니다(규칙은 안전한 쪽으로 읽은 값입니다). 반대로 규칙을 지키는 자세는, 규칙을 만들 때 외피 부품 사이 거리 2.5 mm 이상을 표본 시험으로 확인한 자세들의 범위 안입니다. 구체적인 예는 다음과 같습니다.

- 왼쪽 엉덩이 비틀기 20도: 관절 범위는 -45~45도라 허용되지만, 규칙 B(비틀기 15도 이하)와 규칙 A(엉덩이 옆이 32도 이상이어야 함, 관절 범위는 27도까지)를 모두 어깁니다.
- 어깨 앞뒤 -90도, 어깨 옆 25도, 목 좌우 45도, 목 끄덕임 10도: 각각 범위 안이지만 규칙 E(목 끄덕임 7도 이하)와 규칙 F(이 목 자세에서는 이 어깨 앞뒤 불가)를 어깁니다.
- 모든 관절 0도(0 자세): 어깨 옆이 범위 밖이므로 규칙 D와 F를 어깁니다.
- 홈 자세(MJCF의 `home` 키프레임): 어기지 않습니다.

## 2. 파일

| 파일 | 내용 |
|---|---|
| `coupled_limits_v8.json` | 규칙 A~E의 원본(외피 간격을 잰 결과를 모은 표). 위 설명과 출처 필드가 들어 있습니다. |
| `coupled_limits_v8_armwing.json` | 규칙 G(팔과 등 날개)의 원본 표입니다. |
| `shell_coupled_limits_v8.json` | 위 두 원본을 판정기가 읽기 좋게 변환한 데이터(규칙 F의 표 포함)입니다. **판정기는 이 파일을 읽습니다.** |
| `shell_coupled_limits.py` | 규칙 A~E 판정과 다리 목표 보정 함수 `clip_leg_targets`입니다. 표준 라이브러리만 씁니다. |
| `shell_arm_head.py`, `shell_arm_wing.py` | 규칙 F(팔과 머리)와 규칙 G(팔과 등 날개) 판정입니다. |
| `shell_coupled_checker.py` | A~G를 한꺼번에 판정하는 모듈입니다. 자세를 판정할 때는 이 모듈을 쓰세요. |
| `check_pose.py` | 명령줄 도구입니다(이 저장소에서 새로 쓴 것). |
| `edition_inputs.py` | 모델 생성기에만 있던 설정 모듈을 대신하는 작은 대역입니다(이 저장소에서 새로 쓴 것). 판정기가 데이터 파일 경로를 직접 받게 하는 용도입니다. |

네 판정기 파이썬 파일은 모델 생성기의 복사본이고 내용을 바꾸지 않았습니다.

## 3. 규칙

각도는 도 단위이며 쉬는 자세(어깨 옆 20도, 팔꿈치 -18도)에서의 차이로 계산합니다. 판정기에는 MJCF의 관절 각도(절대값)를 그대로 넣으면 됩니다. 쉬는 자세 값은 데이터 파일(`rest_pose_deg`)이 갖고 있습니다.

| 규칙 | 관계하는 관절 | 내용 |
|---|---|---|
| A 두 다리 사이 | 엉덩이 비틀기와 엉덩이 옆(두 발 덮개가 서로 비켜 가게 하는 규칙) | 엉덩이 옆 >= max(0, -엉덩이 비틀기, 1.6 x 엉덩이 비틀기) |
| B 허리와 다리 | 엉덩이 비틀기 | 20축은 허리가 0도로 고정이라 상수입니다: 엉덩이 비틀기 <= 15도(두 다리). 25축의 허리 범위와 단계표는 없습니다. |
| C 무릎과 발목 | 무릎, 발목 앞뒤 | 무릎 0~60도에서 발목 앞뒤 <= 표(무릎)이고 >= -24도. 무릎이 0~60도 밖이면 다른 관절이 모두 쉬는 자세일 때만 허용 |
| D 팔 상자 | 어깨 옆, 어깨 앞뒤, 팔꿈치 | 어깨 옆 구간 7개마다 어깨 앞뒤와 팔꿈치의 허용 범위 |
| E 목 | 목 좌우, 목 끄덕임 | 목 좌우 +-45도 안에서는 목 끄덕임 -14~11.25도, +-45도를 넘으면 -14~7도(경계 45도 정각은 바깥 상자) |
| F 팔과 머리 | 어깨 앞뒤, 어깨 옆, 목 좌우, 목 끄덕임(팔과 머리 껍데기) | 표(어깨 앞뒤, 팔 쪽으로 돌린 목 좌우, 목 끄덕임)에서 어깨 옆의 상한을 읽음. 상한이 음수면 그 어깨 앞뒤는 불가 |
| G 팔과 등 날개 | 어깨 앞뒤, 어깨 옆, 팔꿈치(팔과 등 날개) | 표 11 x 7칸(어깨 옆, 팔꿈치)에서 어깨 앞뒤의 상한을 읽음 |
| Z 고정 관절 | 허리 비틀기, 팔 돌리기, 손목 돌리기(관절이 아님) | 20축에서 용접된 이 다섯 이름이 0이 아닌 값으로 들어 있으면 위반(25축 자세를 넣을 때의 안전장치) |

한계 경계는 안전한 쪽(엄격한 쪽)으로 읽습니다. 비교 오차는 1e-9도입니다.

## 4. 쓰는 법

명령줄입니다(저장소 맨 위 폴더에서, 표준 라이브러리만 씁니다).

```
python3 -I -B kobi20/shell_rules/check_pose.py --base home
python3 -I -B kobi20/shell_rules/check_pose.py --pose left_hip_yaw_joint=20 --unit deg
python3 -I -B kobi20/shell_rules/check_pose.py --pose left_shoulder_pitch_joint=-90 left_shoulder_roll_joint=25 neck_yaw_joint=45 neck_pitch_joint=10 --unit deg
python3 -I -B kobi20/shell_rules/check_pose.py --pose-json my_pose.json --unit rad --base none
```

- 자세는 "관절 이름 -> 절대 각도"입니다(MJCF의 `qpos`와 같은 값). 주지 않은 관절은 `--base`에서 가져옵니다(기본 `home`: MJCF 키프레임, `zero`: 전부 0, `none`: 가져오지 않음).
- `--base none`에서 일부 관절만 주면 그 관절들이 필요한 규칙은 건너뜁니다(조용히 통과할 수 있으니 관절 20개를 모두 주는 것이 안전합니다).
- 종료 코드는 0(규칙을 어기지 않음), 1(어김), 2(입력 오류)입니다.

파이썬에서는 다음과 같이 씁니다.

```python
import sys
from pathlib import Path
sys.path.insert(0, "kobi20/shell_rules")          # python -I를 쓰면 스크립트 폴더가 자동으로 안 잡힙니다
import shell_coupled_checker as checker

limits = checker.load_limits(Path("kobi20/shell_rules/shell_coupled_limits_v8.json"))   # 경로를 꼭 직접 주세요
violations = checker.check_pose(pose, limits, unit="rad")    # pose: {"left_hip_yaw_joint": 0.1, ...}
for v in violations:
    print(v.rule, v.joint, v.value_deg, v.limit_deg, v.detail)
```

`load_limits()`를 경로 없이 부르면 모델 생성기의 설정을 찾다가 `edition_inputs.py`의 안내 메시지와 함께 멈춥니다. 다리 관절 목표를 규칙 안으로 밀어 넣는 함수 `clip_leg_targets`는 숫자, numpy 배열, jax 배열을 받습니다(`shell_coupled_limits.py`의 설명 참고). 규칙을 어긴 자세를 "고쳐 주는" 것이 아니라 명령을 규칙 쪽으로 투영해 주는 함수이며, 자세가 자유롭다는 증명이 아닙니다.

## 5. 검증

이번에 이 폴더의 파일로 다시 돌려 확인했습니다.

- 홈 자세는 규칙을 어기지 않고, 0 자세는 규칙 D와 F를 어깁니다(어깨 옆 -20도 오프셋이 모든 상자 밖).
- 이 폴더의 판정기와 데이터가, 모델 생성기 폴더에 있는 원래 판정기와 데이터와 같은 답을 내는지 관절 범위 안의 무작위 자세 5,000개로 비교했습니다. 위반 목록(규칙, 관절, 값, 한계)이 한 건도 다르지 않았습니다.
- 모델 생성기 쪽에서는 20축 시험 150개와 25축 회귀 시험 160개가 통과했고, 독립 판정기와의 대조에서 불일치가 0이었다고 기록되어 있습니다. 그 시험 파일은 이 저장소에 넣지 않았습니다.

## 6. 데이터에 대한 설명

- 원본 JSON 두 개는 공개를 위해 세 가지만 고쳤습니다. 규칙의 `where` 설명 안에 있던 부품 폴더 이름 한글 두 낱말을 영어로 바꿨고(외피 -> shell, 모터 -> motor), 측정 원자료 위치를 적은 임시 폴더 경로(운영체제 임시 폴더 아래)를 `scratch/kobi_v6_build/`로 바꿨고, 변환 데이터(`shell_coupled_limits_v8.json`)의 출처 칸(`source`, `extra_sources`)에 있던 작업 폴더 전체 경로를 파일 이름으로 바꿨습니다. 숫자는 바꾸지 않았습니다.
- 원본 JSON을 고쳤으므로 변환 데이터가 적어 둔 원본의 SHA-256(`source.sha256`, `extra_sources[].sha256`)은 이 폴더 파일의 값으로 바꿨습니다. `coupled_limits_v8.json`은 f0e2a9ac...(고치기 전)에서 1b15f996...(이 폴더)로, `coupled_limits_v8_armwing.json`은 05b98fb3...(고치기 전)에서 3b8ce40f...(이 폴더)로 바뀌었습니다.
- 값은 25축 설계에서 외피 부품 사이의 거리를 표본 추출로 재어 만든 것이고(증명이 아닌 표본 시험), 외피 간격이 2.5 mm 이상인 자세의 부분집합을 잡아 두었습니다. 규칙 B와 E의 표시, 규칙 F와 G의 표 읽는 방식은 각 `.py` 파일 머리말에 자세히 있습니다.
